# 9. Why messy data matters for this project

The user specifically wants realistic messy data, not toy datasets.

The synthetic data should be realistic but not impossibly difficult. It should force decisions about:

- whether to impute missing values
- whether to use mean, median, mode, `"Unknown"`, category median, or missing flags
- whether duplicates are real errors or valid repeated events
- whether outliers should be kept, capped, flagged, or quarantined
- whether bad joins come from missing keys, wrong granularity, or source-system problems
- whether model features create leakage
- how cleaning choices affect business KPIs and model results

This is important because real data jobs often involve broken source data, inconsistent formats, duplicated records, missing values, and unclear business logic.
